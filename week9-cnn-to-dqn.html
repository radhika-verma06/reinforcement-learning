Lecture concept

Why experience replay?

Sequential transitions are strongly related to one another. DQN stores transitions in a replay buffer and trains on random mini-batches, reducing that correlation while also reusing old experience.

Lecture concept

Why a target network?

If the same network both predicts Q(s,a) and continuously creates the target, the learner chases a target that moves whenever its own weights change. DQN holds a separate target network fixed for a period, then copies the latest weights across.

Input

What exactly enters the network?

The dataset uses transforms.ToTensor(). A single Fashion-MNIST image is greyscale, so the network sees one channel with spatial size 28×28.

With batch_size=32, the loader hands the model a batch shaped conceptually as [32, 1, 28, 28]: batch, channel, height, width.

Why shuffle?

Train loader vs test loader

The training loader uses shuffle=True, so the order changes between passes through the data. The test loader uses shuffle=False because evaluation does not need random ordering.

The notebook also displays ten images before training, which is a useful sanity check that the input and labels are what you expect.

Output

What is the network trying to predict?

There are ten Fashion-MNIST classes. The final fully connected layer therefore has ten outputs, one position for each possible clothing class.

The supplied solution evaluates the final network on the 10,000-image test set.

Read Conv2d from left to right

nn.Conv2d(1, 32, kernel_size=3, padding=1)

1 is the number of input channels. 32 is the number of learned filters, so the layer produces 32 feature maps. 3×3 is the local window each filter sees.

Why padding 1? For this first 3×3 convolution, one-pixel padding preserves the 28×28 spatial size before pooling.

Then ReLU and MaxPool

ReLU keeps positive activations and inserts non-linearity. MaxPool2d(2, stride=2) downsamples each feature map by taking the strongest value in each 2×2 region.

Pooling changes height and width, but not the number of channels. After the first pooling operation: 32 × 28 × 28 → 32 × 14 × 14.

What forward() is doing

forward defines the path data follows through the model. Each layer transforms the tensor, then out.view(out.size(0), -1) keeps the batch dimension and flattens everything else.

[batch, 128, 2, 2] ↓ view(batch, -1) [batch, 512] ↓ Linear(512, 10) [batch, 10]

The important transition is from a spatial feature representation to a one-dimensional feature vector for the final decision layer.

Action

Each action identifies one board cell. The environment maps that integer back to row and column coordinates.

That gives the DQN exactly 9 possible actions, so the neural network also needs exactly 9 output Q-values.

State.is_end()

Checks all rows, columns and both diagonals. A sum of 3 means player 1 wins; -3 means player -1 wins. A full board with no winner is a tie.

next_state()

Copies the current board, places a symbol at the selected position and returns a new state. This keeps state transition logic separate from the DQN itself.

hash()

The state class also has a board hash. It is part of the supplied state implementation, although the neural DQN learns from the flattened board rather than using a tabular lookup.

The input size is taken from env.observation_space.shape[0]; the output size is taken from env.action_space.n. That makes the network architecture follow the environment definition.

Why the last activation is linear

The last layer is Dense(no_Actions, activation='linear'). A Q-value is an estimate of expected return, not a probability.

So the outputs may be positive or negative and do not need to sum to one. The agent only needs to compare them and choose the largest one during greedy action selection.

Two networks, not one

self.model is the live Q-network. It selects greedy actions and is updated during training.

self.target_model is built with the same architecture but is used to calculate the next-state side of the Bellman target.

Loss and optimiser

The network is compiled with mean-squared error and Adam using lr=0.001. The learning objective is therefore: make the chosen action's current Q estimate closer to the Bellman target.

Epsilon-greedy: where exploration appears in code

get_action() Part B
if np.random.rand() <= self.epsilon:
    return random.randrange(self.env.action_space.n)

act_values = self.model.predict(state, verbose=0)
return np.argmax(act_values[0])

Read it as a decision tree

Explore: with probability epsilon, ignore current Q-values and sample a random action.

Exploit: otherwise, pass the current state through the live network and take the action index with maximum Q-value.

The notebook starts at epsilon=1.0, decays it by 0.999 after each episode, and does not let it intentionally fall below epsilon_min=0.01.

At the start: ε = 1.0 → mostly exploration. Over training: ε decreases → increasingly greedy behaviour.

Replay memory: store first, train from random past experience

The buffer

deque(maxlen=2000) stores at most 2,000 transitions. Each transition is a five-part record:

(state, action, reward, next_state, done)

When the deque is full, older entries are discarded as new ones arrive.

The mini-batch

experience_replay() uses sample_size = 20. If fewer than 20 transitions exist, it returns without training.

Otherwise random.sample chooses 20 transitions rather than simply training on the latest 20 consecutive steps.

Lecture connection. This is the concrete version of experience replay: break the strong correlation of consecutive transitions and reuse older experience instead of consuming each transition only once.

The Bellman target: the centre of DQN

terminal transition: target = reward non-terminal transition: target = reward + gamma × max Q_target(next_state, action')

Why logical_not(dones)?

The notebook multiplies the bootstrapped future term by np.logical_not(dones). If done=True, this factor becomes false/zero, so no future Q-value is added.

That is how one vectorised line handles both terminal and non-terminal samples.

Why the maximum next Q?

This is Q-learning's off-policy target. It asks: from the next state, what is the highest value available according to the target network?

That is different from SARSA, where the update would use the value of the next action actually selected by the behaviour policy.

Core target calculation Part B
targets = rewards + self.gamma *
  np.amax(self.target_model.predict(next_states), axis=1) *
  np.logical_not(dones)

target_vec = self.model.predict(states)
target_vec[indexes, actions] = targets
self.model.fit(states, target_vec, epochs=1, verbose=0)

Why only replace target_vec[indexes, actions]?

For each sampled transition, only one action was actually taken. The Bellman calculation therefore gives a learning target for that action's Q-value.

The other output positions are left at their current predictions. This is the neural equivalent of changing one Q-table cell for each transition.

Why checkpoint?

The callback saves model snapshots while the same training process continues. In the notebook, save_interval = 200000 // 3, so multiple training stages can be compared.

A checkpoint is useful evidence because it lets you ask whether the agent's behaviour is actually improving, rather than seeing only a final score.

Maximum capacity of replay memory. The notebook explicitly says replay stores past experience and samples it randomly to break temporal correlation.

Smaller:Old experience is replaced sooner.
Larger:More historical diversity, more RAM.

The final random-action probability. Once the schedule has finished, the agent still explores about 10% of action selections instead of becoming completely greedy.

Lower:More greedy final behaviour.
Higher:Persistent exploration but more random late actions.

exploration_fraction = 0.12

Fraction of the whole training run over which epsilon is reduced. With 200,000 timesteps, 12% means the decay window lasts about 24,000 timesteps.

Smaller:Become greedy earlier.
Larger:Keep exploring for longer.

The Bellman discount factor. It controls how strongly future reward contributes to today's target. Values closer to 1 preserve delayed reward for longer.

Lower:More short-sighted return.
Higher:Longer reward horizon; future estimation matters more.
Try: 0.90 · 0.95 · 0.99

gradient_steps = -1

The notebook defines -1 as “perform as many gradient steps as environment steps collected during the rollout.” This controls how much optimiser work happens after collecting experience.

Fewer:Less optimisation per new data.

  nn.Conv2d(observation_space.shape[0], 32, kernel_size=8, stride=4),
  nn.ReLU(),
  nn.Conv2d(32, 64, kernel_size=4, stride=2),
  nn.ReLU(),
  nn.Conv2d(64, 64, kernel_size=3, stride=1),
  nn.ReLU(),
  nn.Flatten()
)
self.linear = nn.Sequential(nn.Linear(n_flatten, 512), nn.ReLU())

What each design choice means

First input channels: taken directly from observation_space.shape[0], so the extractor adapts to the observation format supplied by the Atari wrapper.

Large early kernel + stride: the first layer uses 8×8 with stride 4, reducing spatial resolution quickly while learning broad visual features.

Deeper layers: 32 channels become 64, then remain 64 as spatial features become more abstract.

512 features: the flattened convolutional output is mapped into a 512-dimensional feature vector for the policy.

Why calculate n_flatten with a sample?

The notebook does not hard-code the flattened convolution size. Instead it samples a valid observation, temporarily runs it through self.cnn under torch.no_grad(), and reads .shape[1].

sample observation ↓ custom conv stack [1, n_flatten] ↓ Linear(n_flatten, 512) 512 extracted features

Why this is useful

If the upstream observation shape or convolution geometry changes, manually calculating the flatten size is easy to get wrong. The sample-forward technique lets the code derive the correct number from the architecture itself.

This is the RL version of the Part A shape discussion, but automated.

The important line is policy_kwargs

CnnPolicy tells SB3 this is an image-style policy. The custom class is then supplied through features_extractor_class.

That means SB3 can still own replay, target updates and optimisation while the state representation comes from your own CNN.
