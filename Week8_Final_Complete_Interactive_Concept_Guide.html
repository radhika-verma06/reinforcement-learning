RL notation needed before Week 8

State · s

What the agent currently knows about the environment.

Action · a

A choice available to the agent in the current state.

Reward · r

Immediate feedback received after an action.

Return · G

Cumulative future reward the agent ultimately cares about.

State value

One number for the state.

Action value

Q(s,a) = expected return if action a is taken in state s

One number for each state-action pair.

Function approximation: learning the rule instead of memorising every case

A function approximator receives an input and predicts an output. In reinforcement learning, that output can later be a value such as V(s) or Q(s,a).

The basic idea

true relationship: y = f(x)
learned approximation: ŷ = f̂(x; θ)

θ means the parameters the model can change, such as weights and biases.

1
Give the model an input x.
2
The model produces prediction ŷ.
3
Compare ŷ with true target y.
4
Adjust θ to make future predictions better.

Why RL needs this

Q-tableFunction approximation
Stores a separate value for each state-action pair.Learns a mapping that can produce values from inputs.
Natural for small discrete spaces.Useful when spaces become large or continuous.
Little generalisation between different rows.Shared parameters can generalise across similar inputs.
DQN connection: instead of asking a table for Q[s,a], a neural network computes an estimate Q(s,a; θ).
Notebook 1 · neural-network foundations

Before reading the code: the basic neural-network words

The first notebook uses Keras, but the code becomes much easier once these words are separated. A neural network is simply a parameterised function that makes a prediction, measures how wrong it was, and adjusts its parameters.

Weight w

A weight controls how strongly an input influences a neuron.

z = w·x + b

Memory example: if house size matters strongly for price, the model may learn a larger weight on house size.

Bias b

Bias is an extra learned offset. It lets the neuron shift its output instead of forcing the line/function through zero.

without bias: y = wx
with bias: y = wx + b

Neuron

A neuron first computes a weighted sum and then, in a hidden layer, usually applies an activation function.

input → weighted sum → activation → output

Activation function: why do we need it?

An activation function changes the neuron's weighted sum before passing it forward. Its main purpose in hidden layers is to give the network nonlinearity.

z = w·x + b
activation = ReLU(z) = max(0,z)

If every layer were only linear, stacking many layers would still behave like one large linear transformation. ReLU lets the network build more flexible relationships.

→ ReLU →
0
z = 3.5
→ ReLU →
3.5
Notebook link: the hidden layer uses activation='relu', while the final regression output uses activation='linear' because price/MPG are continuous numeric outputs.

Remember: loss is the score of the mistake; optimiser is the correction strategy.

Controls how large each optimiser update is. Too large can overshoot; too small can learn very slowly.

TD control before Double Q-Learning

Temporal-Difference control learns action-values while interacting with the environment. The notebook supplies helper functions for epsilon-greedy action selection, policy extraction, plotting, and simulation.

TD update idea

new estimate = old estimate + α × (target − old estimate)
α
learning rate
How strongly one update changes the estimate.
target
reward + estimate of future
What the current value is being pulled toward.
TD error
target − current estimate
The correction signal.

Q-Learning target

target = r + γ maxₐ Q(s',a)

r: immediate reward.

γ: discount factor controlling the weight of future rewards.

s': next state.

max: assumes the best-valued next action is followed.

Epsilon-greedy behaviour policy

random number < ε → explore randomly
otherwise → argmax Q[state]

Exploration tries actions to gather information. Exploitation chooses the best-known action.

epsilon ε0.10
def epsilon_greedy_policy(Q, state, epsilon):
    if np.random.rand() < epsilon:
        return np.random.choice(len(Q[state]))
    else:
        return np.argmax(Q[state])

Extract policy from learned Q

policy[s] = argmaxₐ Q(s,a)

This returns the action index with the largest Q-value in each state.

Extract V from learned Q

V(s) = maxₐ Q(s,a)

Once Q-values exist, the best action value in a state can be used as that state's greedy state value.

Notebook 2 · helper functions

Two tiny functions that make the rest of the notebook readable

def extract_policy_V_from_Q_flat(Q, env):
    n_states = env.observation_space.n
    policy = np.empty(n_states, dtype=np.int64)
    V = np.empty(n_states, dtype=np.float64)

    for state in range(n_states):
            policy[state] = np.argmax(Q[state, :])
            V[state] = np.max(Q[state, :])

    return policy, V

argmax vs max

Q-values
[2, 7, 4, 1]
→
argmax = 1
max = 7

argmax gives the index/action. max gives the value. So policy needs argmax; V needs max.

def update_epsilon(episode, initial_epsilon=1.0, min_epsilon=0.05, decay_factor=0.99):
    decayed_epsilon = (initial_epsilon - min_epsilon) * np.exp(-decay_factor * episode)
    epsilon = min_epsilon + decayed_epsilon
    return epsilon

Episode number enters the exponential decay. Early on epsilon is near 1, so exploration is high. As episode number grows, the exponential part shrinks and epsilon approaches 0.05.

Remember epsilon as curiosity: a beginner explores a lot; an experienced agent mostly uses what it has learned but keeps a little curiosity.
The main algorithm

Why Double Q-Learning uses two Q-tables

The overestimation problem

Q-Learning uses a maximum over estimated values. If estimates contain noise, the maximum tends to select values that are accidentally too high.

same estimates choose + evaluate:
maxₐ Q(s',a)
Important: this does not mean Q-Learning is always wrong. It means the maximisation step can introduce an optimistic bias when value estimates are uncertain.

Double Q idea

Maintain two estimates: Q1 and Q2. One table chooses an action, while the other table evaluates that chosen action.

Q1 chooses
→
Q2 evaluates

or randomly swap roles

Q2 chooses
→
Q1 evaluates

Interactive selection vs evaluation

Suppose next-state estimates are:

Q1(s', ·)
Q2(s', ·)

The exact update structure in the notebook

a* = argmaxₐ Q1(s',a)
target = r + γ Q2(s', a*)
Q1(s,a) ← Q1(s,a) + α[target − Q1(s,a)]

Q1 selects. Q2 evaluates that selected action. Q1 is the table being updated.

a* = argmaxₐ Q2(s',a)
target = r + γ Q1(s', a*)
Q2(s,a) ← Q2(s,a) + α[target − Q2(s,a)]

Q2 selects. Q1 evaluates that selected action. Q2 is the table being updated.

if np.random.rand() < 0.5:
    best_next_action = np.argmax(Q1[next_state, :])
    TD_target = reward + gamma * Q2[next_state, best_next_action]
    TD_error = TD_target - Q1[state, action]
    Q1[state, action] += alpha * TD_error
else:
    best_next_action = np.argmax(Q2[next_state, :])
    TD_target = reward + gamma * Q1[next_state, best_next_action]
    TD_error = TD_target - Q2[state, action]
    Q2[state, action] += alpha * TD_error

Why the 50/50 random choice?

np.random.rand() < 0.5 decides which table gets updated on that time step. Over many steps, both receive learning updates.

The table choice is random; the best next action within the selected table is still chosen with argmax.

Why action selection uses Q1 + Q2

action = epsilon_greedy_policy(Q1 + Q2, state, epsilon)

The notebook combines both learned estimates for its behaviour action selection. Exploration is then layered on top through epsilon-greedy.

Epsilon decay used in the notebook

ε = ε_min + (ε_initial − ε_min) × exp(−decay_factor × episode)
episode0

With defaults initial=1.0, min=0.05, decay_factor=0.99, exploration starts high and rapidly approaches the minimum.

Why Double Q-Learning here is off-policy: the agent behaves epsilon-greedily, meaning it sometimes takes exploratory actions. The TD target, however, uses a greedy next-action choice through argmax. Behaviour and target policies are therefore not identical.
Notebook 2 · main loop

Read Double Q-Learning as a repeating 7-step story

for episode in range(num_episodes):
    epsilon = update_epsilon(episode)
    state, info = env.reset()

    while True:
        action = epsilon_greedy_policy(Q1+Q2, state, epsilon)
        next_state, reward, terminated, truncated, info = env.step(action)
        done = terminated or truncated

Two-judge memory trick

Imagine two judges scoring the same performance.

If Judge 1 chooses the favourite, Judge 2 gives the score. Next time their roles might reverse.

This separation reduces the chance that one overly optimistic estimate both chooses itself and validates itself.

Notebook 2 · the part that usually causes confusion

Exactly how Q1/Q2 are chosen, and why the evaluation can be lower

There are three different choices happening in the loop. They are easy to mix up: (1) which environment action the agent takes, (2) which Q-table gets updated, and (3) which next action is selected for the TD target.

Choice 1 · behaviour

Which action do I take now?

epsilon_greedy_policy(Q1 + Q2, state, epsilon)

The agent acts using the combined estimates Q1 + Q2, with exploration controlled by epsilon.

Choice 2 · update table

Which table learns this step?

if np.random.rand() < 0.5:

A random number in [0,1) acts like a fair coin. Less than 0.5 → update Q1. Otherwise → update Q2.

Choice 3 · TD target

Who selects and who evaluates?

If Q1 is being updated, Q1 selects the next action and Q2 evaluates that exact action. If Q2 is being updated, the roles reverse.

Interactive coin flip: which Q-table gets updated?

np.random.rand() < 0.5 does not mean “Q1 is better”. It only decides which estimator receives the update on this particular step.

One next state, four possible actions

CliffWalking prints Discrete(4), so every state has four action choices: 0 Right, 1 Down, 2 Left, 3 Up. Therefore a row such as Q1[next_state, :] contains four values, one estimate per action.

Read the code literally

best_next_action = np.argmax(Q1[next_state, :])
TD_target = reward + gamma * Q2[next_state, best_next_action]
1
Q1[next_state, :] gives all 4 estimates: [2.1, 4.8, 3.9, 4.2].
2
np.argmax(...) returns the index of the largest value: index 1. It returns 1, not 4.8.
3
Now use that same index in Q2: Q2[next_state, 1] = 3.1.
4
So Q2 does not ask “what is my favourite action?”. It answers “what do I think about the action Q1 chose?”

Why can Q2's evaluation be lower than Q1's maximum?

Q1 and Q2 learn from different random updates, so at any moment they contain slightly different estimates. Rewards, exploratory actions and incomplete experience make the estimates noisy.

Suppose action 1 is truly worth about 3.5. By chance, Q1 may currently estimate it as 4.8 while Q2 estimates it as 3.1. If ordinary Q-Learning lets the same noisy table both select the maximum and use that maximum as the evaluation, the lucky high error can feed directly into the target.

Double Q breaks that self-confirmation. Q1 may still select action 1 because of its 4.8, but Q2 evaluates that exact action as only 3.1.

Q1 a0
2.1
Q1 a1
4.8
Q2 a1
3.1
Memory trick: Q1 says, “I nominate action 1.” Q2 replies, “Fine, but my score for action 1 is 3.1.” Selection and evaluation are deliberately separated.
Small notebook-comment trap: inside the supplied code, the comment above the Q1 branch says “Update Q1 using max action from Q2”. The executable lines actually do argmax(Q1[next_state,:]) and then evaluate with Q2[...]. For understanding the algorithm, follow the executable lines: the table being updated selects; the other table evaluates.

Complete numeric TD update using the example

Assume reward = −1, gamma = 1, current Q1[state, action] = 2.0, and alpha = 0.1.

best_next_action = argmax([2.1, 4.8, 3.9, 4.2]) = 1
evaluation from Q2 = Q2[next_state, 1] = 3.1
TD target = −1 + 1 × 3.1 = 2.1
TD error = 2.1 − 2.0 = 0.1
new Q1[state,action] = 2.0 + 0.1 × 0.1 = 2.01

The selected action's Q1 estimate was 4.8, but 4.8 never enters the evaluation term. It is used only to obtain the action index. That is the central Double Q idea.

What problem are CliffWalking and Taxi actually helping us solve?

Double Q-Learning is the algorithm we are studying. CliffWalking and Taxi are not separate algorithms. They are two small problems used to test whether the same Double Q-Learning idea can learn useful action-values in different environments.

The RL problem stays the same

state → choose action → receive reward → next state → update Q

In every environment, the agent must learn: “When I am in this state, which action will give me the best long-term outcome?”

Q-Learning, SARSA and Double Q-Learning all answer this using Q(s,a). The environment only changes what state, action and reward mean.

Same algorithm, different story

Agentwalkertaxi
Statecurrent grid celltaxi position + passenger + destination
Actionmove in 4 directionsmove + pickup/dropoff
Rewardpenalises steps/cliffpenalises steps/illegal service, rewards delivery
Goalreach goal safely and quicklypick up and deliver correctly
Remember: CliffWalking and Taxi are like two exam questions testing the same method. Double Q-Learning is the method. The grid/taxi story is just the problem the method is applied to.

CliffWalking linked to algorithms you already know

AlgorithmWhat it uses for the next-state targetEasy interpretation
SARSAQ(s′, action actually chosen next)“Learn from what I am really about to do.” With exploration still active, it can value safer routes because a random move near the cliff is dangerous.
Q-Learningmax Q(s′,a)“Assume I take the best action next.” It learns the greedy optimal route, but the same estimates both choose and evaluate the maximum.
Double Q-Learningone Q selects, the other evaluates“Choose with one opinion, check with another.” It keeps Q-Learning's off-policy idea while reducing optimistic max bias.
Why CliffWalking is useful here: the consequences of a poor action are visually obvious. A slightly over-optimistic action value near the cliff can represent a genuinely risky decision, so it is a simple environment for seeing how learned Q-values become a route.

One step as an RL transition

cell s → action Right → reward −1 → next cell s′ → update Q(s, Right)

The algorithm does not understand “cliff” as a word. It only sees state numbers, action numbers and rewards. After many transitions, actions leading toward the goal without repeatedly receiving large penalties become more valuable.

Why γ = 1.0 is reasonable here

The notebook describes CliffWalking as an undiscounted episodic task. With γ=1, future rewards are not reduced purely because they happen later.

return = r₁ + r₂ + r₃ + ...

Extra steps still hurt because each normal move adds another −1.

7000 episodes: repeated experience.

alpha 0.01: relatively small update size.

Plots produced by the supplied CliffWalking notebook

The notebook calls plot_episode_stats(stats). It creates these three figures from the recorded training statistics.

1 · Episode Length over Time. Early episodes can be extremely long because the agent has not yet learned a good route and epsilon is high. The sharp fall means the learned behaviour reaches terminal states in far fewer steps. Lower episode length here is generally evidence that navigation is becoming more efficient.
2 · Smoothed Episode Reward. CliffWalking gives −1 for ordinary moves and a much larger negative penalty for the cliff. Very negative early returns therefore mean long/poor trajectories and cliff penalties. As the curve rises toward zero, episodes are accumulating much less negative reward. The plot is smoothed over a window of 10 episodes, so it shows the trend rather than every individual spike.
3 · Episode versus cumulative time steps. The x-axis is total environment steps consumed so far. The curve becomes steeper because later episodes tend to require fewer steps, so many more episodes can be completed for each additional block of interaction.
4 · State-Value Function. Each cell is V(s)=max_a Q(s,a) after combining Q1 and Q2. Values become less negative as states get closer to the goal because fewer −1 moves remain. The bottom-row cliff cells show 0 in this output because they are not ordinary traversable decision states in the learned trajectory; do not interpret 0 as “the cliff is good”.
5 · Policy Plot. The number in each cell is the selected action index, not a Q-value magnitude: 0 Right, 1 Down, 2 Left, 3 Up. For example, a cell labelled 1 means the extracted greedy policy chooses Down there. Bottom cliff/terminal-region entries should not be over-interpreted because those states are not used like normal decision cells.
How the two grid plots are produced: first the notebook forms the final estimate Q = Q1 + Q2. Then for each state it uses np.argmax(Q[state,:]) for the policy and np.max(Q[state,:]) for V. argmax gives the action index; max gives the value itself.

Why Taxi is the second test

CliffWalking mainly tests navigation. Taxi makes the decision problem richer: the agent must not only move, but also decide when pickup and dropoff are legal and useful. This shows that Double Q-Learning is not a “cliff algorithm”; it is a general tabular TD-control method.

Taxi state = where is the taxi? + where is the passenger? + where must the passenger go?

That is why two taxis standing on the same square can still be in different RL states: the passenger or destination may be different.

Link to Q-Learning you already completed

The training loop is almost the same idea as ordinary Q-Learning: use epsilon-greedy behaviour, take a step, receive a reward and update an action-value. The important change is the target calculation. Ordinary Q-Learning uses one table's maximum. Double Q-Learning keeps two estimates and separates selection from evaluation.

Simple memory example: Q-Learning is one GPS both choosing and rating its own route. Double Q-Learning is GPS A proposing the next turn and GPS B independently rating that same turn. Taxi then asks whether this idea still works when the task includes pickup/dropoff decisions, not just movement.

Notebook 3 · DQN

DQN: Q-Learning, but the Q-table is replaced by a neural network

Do not treat DQN as a completely new algorithm. Start with the Q-Learning idea you already know, then change only one thing: instead of storing every Q-value in a table, a neural network predicts the Q-values.

Q-Learning

state → Q-table → Q-values → choose action

Look up the current state and compare the Q-values for its possible actions.

DQN

state → neural network → Q-values → choose action

The network predicts those Q-values. The action with the largest valid Q-value is the greedy choice.

Memory line: DQN = Q-Learning + neural network. Same goal: learn which action is valuable. Different storage: network instead of a huge Q-table.

Tic-Tac-Toe example

The board has 9 squares, so the DQN can output one Q-value for each action 0–8.

board [9 numbers] → DQN → [Q0, Q1, Q2, ... Q8]

Example: if the largest valid output is Q7, the agent chooses action 7. In this board, divmod(7,3) = (2,1), so that means row 2, column 1.

How does it learn?

See board
→
Choose move
→
Get reward
→
Update network

Good outcomes should make useful moves more valuable. Bad outcomes should make poor moves less valuable. Repeating this over many games improves the network's Q-value estimates.

Replay buffer

A memory of previous game steps. DQN reuses samples from this memory while learning.

Target network

A slower copy used to make learning more stable. For this class, remember its purpose rather than its internal maths.

Exploration

During training the agent sometimes tries a move instead of always choosing its current favourite, so it can discover better actions.

What SB3 is doing for us: the notebook's DQN(...) and model.learn(...) handle much of this machinery. The main concept to leave with is board → network → Q-values → action → reward → learn.

Why an invalid action gets a big penalty

If the model chooses an occupied square, that move is illegal. The notebook returns reward −10.

occupied cell → same board + reward −10

The purpose is to make invalid choices unattractive to the learned Q-function.

Supplied-code detail: despite the nearby notebook comment saying “terminate”, the actual return has terminated=False and truncated=False, so that branch does not itself end the episode.

How does the code know someone won?

The State.is_end() method checks each row, each column and both diagonals. Because O is +1 and X is −1:

sum = +3 → O filled all three cells
sum = −3 → X filled all three cells

If every square is filled and there is no ±3 line, the game is a draw.

Notebook 3 · State class code

How the class represents and checks a Tic-Tac-Toe board

class State:
    def __init__(self):
        self.data = np.zeros((BOARD_ROWS, BOARD_COLS))
        self.winner = None
        self.hash_val = None
        self.end = None

    def next_state(self, i, j, symbol):
        new_state = State()
        new_state.data = np.copy(self.data)
        new_state.data[i, j] = symbol
        return new_state

data is the 3×3 board.

winner stores who won once known.

next_state does not overwrite the old state directly; it creates a copied board with one move added.

Remember: a state is like a photo of the board at one moment. next_state creates the next photo after a move.
sum_values = np.sum(np.abs(self.data))
if sum_values == BOARD_SIZE:
    self.winner = 0
    self.end = True
    return self.end

Why absolute values?

O is +1 and X is −1. Without abs, an O and X could cancel. Taking absolute value turns every occupied square into 1.

→
sum(abs(board)) = 9
there are no empty cells

How TicTacToeEnv turns the game into an RL problem

Action space

spaces.Discrete(BOARD_SIZE) = Discrete(9)

The agent chooses one integer from 0 to 8.

action4

Observation space

spaces.Box(low=-1, high=1, shape=(9,), dtype=int)

The observation is a length-9 vector. Each element is restricted conceptually to −1, 0, or 1 by the game encoding.

Action ≠ observation. Action is one integer telling the environment where to move. Observation is the whole current board represented as nine values.

3
Draw toss_outcome from 1,2,3,4.
4

5

single mode

The environment plays the other side using _make_env_move(), which randomly selects an available square.

Reward function can give +1 for win, −1 for loss, and 0 otherwise.

double mode

The environment does not insert a separate random opponent move after the agent step. The notebook trains with:

env = TicTacToeEnv("double")

Its reward helper gives +1 for a win and otherwise 0.

step(action): the most important environment method

1
Convert action number into row and column:
i, j = divmod(action, BOARD_COLS)
2
If the cell is already occupied, return the unchanged flattened state and reward −10.
3
Otherwise create the next board using next_state(i,j,current_player).
4
Call is_end() to decide whether the game naturally ended.
5
Choose the reward helper based on mode and compute reward.
6
If not terminated, switch player using current_player *= -1.
7
In single mode only, the environment can then make its random move and the terminal state is checked again.
8
Return the Gymnasium step tuple: observation, reward, terminated, truncated, info.

Invalid action: notebook comment vs actual code

# comment says: "penalize ... and terminate"
return self.state.data.flatten(), -10, False, False, {}

Actual code behaviour: reward is −10, but terminated=False and truncated=False. Therefore this return does not terminate the episode.

terminated vs truncated

terminated: the task reaches a natural terminal condition, such as game over.

truncated: an external limit stops the episode, such as a time limit. This custom environment explicitly sets truncated=False.

What happens when the notebook calls model.learn(50000)?

The code looks short because Stable-Baselines3 hides the internal DQN machinery. Conceptually, learning repeatedly cycles through environment interaction and neural-network updates.

DQN selects the Deep Q-Network algorithm implementation.

verbose=2 controls printed training information.

Important: one timestep is one interaction step, not necessarily one full Tic-Tac-Toe game. A game/episode contains several timesteps.

A concrete Tic-Tac-Toe DQN update

Suppose the current board is s. DQN chooses action 4 and receives reward 0 because the game is not over yet.

current predicted Q(s,4) = 0.30

From the next board, suppose the target calculation produces:

target = r + γ·best_next_value = 0 + 0.99×0.80 = 0.792

The network's prediction 0.30 is below the target 0.792, so optimisation adjusts weights to push the relevant prediction closer to the target.

This is the same idea as Notebook 1: prediction → target → loss → optimiser updates weights. The difference is that the target now comes from RL experience rather than a fixed labelled dataset.
