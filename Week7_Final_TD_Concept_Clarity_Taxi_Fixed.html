1. Before the notebooks: why Temporal Difference?

QUESTION
Why not just keep using Monte Carlo?
SIMPLE IDEA
Monte Carlo waits for the full return. TD learns after every single transition.
YOU SHOULD LEAVE KNOWING
TD target = real reward now + our current estimate of what comes next.
Quick check: Does TD need the episode to finish before it learns?
No. That is the point of TD: it can update after one step.
Start with the problem: Monte Carlo waits for an episode to finish. TD says: “I already saw one reward and one next state, so I can learn something now.”

Dynamic Programming

Needs the environment model: transition probabilities and rewards.

“If I take action a in state s, what are all possible next states and probabilities?”

Monte Carlo

No model needed, but it waits until the end of the episode to know the return G.

V(Sₜ) ← V(Sₜ) + α[Gₜ − V(Sₜ)]

TD(0)

No model needed and no need to wait for the episode to finish. Update after one transition.

V(Sₜ) ← V(Sₜ) + α[Rₜ₊₁ + γV(Sₜ₊₁) − V(Sₜ)]

Where does the TD target come from?

Monte Carlo target
Gₜ = Rₜ₊₁ + γRₜ₊₂ + γ²Rₜ₊₃ + ...
Accurate sample of the full future, but must wait.
→
TD target
Rₜ₊₁ + γV(Sₜ₊₁)
Use one real reward, then bootstrap from our current estimate of the next state.
Bootstrapping means we update one estimate using another estimate. V(Sₜ₊₁) is not the true future return. It is the current guess.

Vocabulary to lock in before we continue

TermMeaning
TD targetR + γV(S′), the value we want the current estimate to move toward.
TD errortarget − current estimate.
αHow strongly we move toward the new target.
γHow much future value matters.
PredictionEvaluate a policy that is already given.
ControlLearn/improve the policy itself.

Numerical TD(0) example

Suppose V(S)=4, reward=-1, V(S′)=6, α=0.1, γ=1.

Target = -1 + 1×6 = 5
TD error = 5 − 4 = 1
New V(S) = 4 + 0.1×1 = 4.1

Interpretation: “I used to think S was worth 4. One step of evidence suggests it should be about 5, so I move only 10% of the way toward 5.”

Easy way to remember: “Monte Carlo says: finish the whole movie, then review it. TD says: after every scene, update your opinion using what just happened plus your current guess about what comes next.”

2.2 Deterministic policy used in the solution

CliffWalking action numbers

0 = ↑ UP
1 = → RIGHT
2 = ↓ DOWN
3 = ← LEFT

How to read the policy

Whenever the code returns a number, that number is an action. So return 0 means “move UP”, return 1 means “move RIGHT”, and so on.

def cliffwalking_deterministic_policy(env, state):
    row, col = divmod(state, 12)
    if state == 36:
        return 0          # 0 = UP from the start
    if col == 11:
        return 2          # 2 = DOWN in the last column
    return 1              # 1 = RIGHT everywhere else
Follow the route step by step:
1. Start at state 36 = (3,0), the bottom-left cell.
2. The policy returns 0 = UP, so the agent moves to row 2.
3. From row 2, the policy keeps returning 1 = RIGHT, so it moves across the grid above the cliff.
4. When it reaches the last column, col == 11, the policy returns 2 = DOWN until it reaches the goal at state 47.

So the path is: ↑ once → → → ... across row 2 → ↓ at the final column. It avoids stepping onto the cliff cells in the bottom row.
Important source-code comment issue: the solution notebook comment says “Assuming 36 is the goal state”. In CliffWalking, state 36 is the start, not the goal. The goal is 47. Teach the behaviour, not that incorrect comment.

2.3 TD(0) code anatomy

V = np.zeros(env.observation_space.n)
for episode in range(num_episodes):
    state, info = env.reset()
    while True:
        action = policy(env, state)             # FIXED policy
        next_state, reward, terminated, truncated, info = env.step(action)
        V[state] += alpha * (reward + gamma * V[next_state] - V[state])
        state = next_state
        if terminated or truncated:
            break

policy(env,state)

Decides what to do. TD(0) is not changing it.

env.step(action)

Gives one real experience: S, A, R, S′.

V update

Moves V(S) toward R + γV(S′).

Important terminal-state idea: a robust implementation normally uses zero bootstrap at a terminal transition: target = R if done, otherwise R + γV(S′). The supplied solution updates with V[next_state] directly. In these tabular toy tasks this may still appear to work because terminal values are initially zero, but conceptually you should know terminal future value is 0.

2.4 Why some V values stay zero

A deterministic policy visits only a subset of states. TD(0) only updates states it actually encounters. So unvisited states can remain at their initial value. Zero does not mean “this state is actually worth zero”; it can simply mean “we never learned about it.”

3.2 Old notebook policy — very simple rule

    return SOUTH
elif row > target_row:
    return NORTH

What is it thinking?

“Get onto the target row. Then move left/right until I reach the target column.”

That sounds sensible, but it only compares coordinates.

It never asks: “Can I actually move through this side of the cell?”

3.5 Why does BFS return only the first action?

BFS may find a whole route such as:

NORTH → EAST → EAST → SOUTH → EAST

But the policy only needs to answer one question:

“What should Taxi do right now?” → return NORTH.

After Taxi moves, the policy is called again from the new state.

4. Notebook Part B — SARSA: learn actions with TD

BEFORE SARSA
TD(0) learned V(s) for a policy we already gave it.
NOW
SARSA learns Q(s,a), so the agent can compare actions and improve its behaviour.

SARSA learns from the next action it actually chooses.
Big jump: Prediction asks “How good is this state under my policy?” Control asks “Which action should I choose from this state?”

4.1 Why do we change from V(s) to Q(s,a)?

V(s)

One number for a state.

V(s) = how good is this state?

Q(s,a)

One number for every action in a state.

Q(s,a) = how good is action a here?

Why Q helps

If Q values are [2, 8, −3, 4], choose the action with value 8.

Quick check: If I only know V(s)=10, do I know which action produced that value?
No. V rates the state. Q separates the actions, which is why control algorithms learn Q.

4.3 ε-greedy — how the notebook chooses an action

def epsilon_greedy_policy(Q, state, epsilon):
    if random.uniform(0, 1) < epsilon:
        return env.action_space.sample()       # explore
    else:
        return max(range(env.action_space.n),
                   key=lambda a: Q[state, a])  # exploit

Explore

With probability ε, try a random action.

Exploit

Otherwise choose the action with the largest current Q-value.

Why both?

Only exploiting too early can trap us with a bad first guess. Exploration lets us discover alternatives.

Interactive: what does ε actually mean?

Move ε, then simulate 100 action choices.

ε0.10
At ε = 0.10, we expect roughly 10 random exploration choices out of 100.
⚠️
When Q starts as all zeros: the greedy choice is not genuinely “smart” yet. Several actions are tied. Exploration is what gives the agent varied experience so the Q-values can begin to separate.

4.4 Why is it called SARSA?

St → At → Rt+1 → St+1 → At+1

S, A

Current state and the action we take.

R, S′

Environment gives a reward and next state.

A′

SARSA chooses the next action before it updates Q.

Why choose A′ before updating? Because A′ itself is part of SARSA’s TD target. The update asks: “What happened now, plus what is the value of the action my current policy will actually take next?”

4.5 SARSA update — read it as three small ideas

Q(S,A) ← Q(S,A) + α [ R + γQ(S′,A′) − Q(S,A) ]

1. Target

R + γQ(S′,A′)

Immediate reward + estimated future from the next chosen action.

2. TD error

target − Q(S,A)

How far our old estimate is from the new target.

3. Update

old Q + α × error

Move part of the way toward the target.

4.6 One SARSA update, slowly

Suppose Q(S,A)=2, reward = −1, γ=1, α=0.5. At the next state, ε-greedy actually chooses A′ and Q(S′,A′)=5.

Target = −1 + 1×5 = 4
TD error = 4 − 2 = 2
New Q = 2 + 0.5×2 = 3
Why didn't SARSA use the best next Q-value?
Because SARSA is learning the value of the policy it is actually following. If ε-greedy chooses A′, SARSA uses that A′.

4.7 Notebook fill-in-the-blanks — completed teaching version

Read the policy directly from the code:
1. Behaviour policy: epsilon_greedy_policy(...) chooses the action actually sent to env.step(action).
2. Target policy: SARSA uses epsilon_greedy_policy(...) again to choose A′ for Q(S′,A′).
Same rule for both jobs → behaviour = target → ON-POLICY.

This mirrors the structure of the Part B algorithm cell, but fills the blanks so you can see why each line exists.

def sarsa(env, num_episodes, gamma=1.0, alpha=0.85, epsilon=0.1):
    # 1) one Q value for every state-action pair
    Q = np.zeros((env.observation_space.n, env.action_space.n), dtype=float)


    stats = EpisodeStats(
        episode_lengths=np.zeros(num_episodes),
        episode_rewards=np.zeros(num_episodes))


    for episode in range(num_episodes):
        state, _ = env.reset()


        # ===== BEHAVIOUR POLICY =====
        # This chooses the REAL action A that the agent will take.
        # In this notebook, the behaviour policy is epsilon-greedy.
        action = epsilon_greedy_policy(Q, state, epsilon)
        timeStep = 0


        while True:
            # The environment actually follows the BEHAVIOUR action above.
            nextstate, reward, terminated, truncated, info = env.step(action)
            done = terminated or truncated


            # ===== TARGET POLICY =====
            # SARSA also chooses A' using epsilon-greedy.
            # So the TARGET policy is the SAME as the BEHAVIOUR policy.
            # behaviour = epsilon-greedy
            # target    = epsilon-greedy
            # SAME POLICY => SARSA is ON-POLICY.
            nextaction = epsilon_greedy_policy(Q, nextstate, epsilon)


            # 4) record what happened this episode
            stats.episode_rewards[episode] += reward
            timeStep += 1
            stats.episode_lengths[episode] = timeStep


            # ===== SARSA LEARNING TARGET =====
            # The A' inside Q[nextstate, nextaction] came from the SAME
            # epsilon-greedy policy that controls behaviour.
            # This is the exact line where behaviour = target becomes visible.
            TD_target = reward if done else reward + gamma * Q[nextstate, nextaction]
            TD_error = TD_target - Q[state, action]
            Q[state, action] += alpha * TD_error


            # A' now becomes the REAL next action A.
            # So SARSA learns from the action it is actually going to take.
            state = nextstate
            action = nextaction


            if done:
                break


    return Q, stats

Why carry action forward?

The A′ used in the update becomes the actual A on the next step.

Why zero bootstrap on done?

Once the episode has ended, there is no future state value to add.

What are stats for?

They do not train the agent. They only let us inspect learning progress.

🏁
Terminal transition: once the episode is finished there is no future action-value to bootstrap from. Conceptually, the target becomes just the final reward R. This is why robust implementations multiply the bootstrap term by “not done” or handle terminal states separately.

4.9 From Q-table to a usable policy

for state in range(env.observation_space.n):
    policy[state] = np.argmax(Q[state, :])
    V[state] = np.max(Q[state, :])
Two things from one row of Q: argmax gives the best action index; max gives the value of that best action.

4.10 Why SARSA is on-policy

Behaviour policy = ε-greedy    AND    Target uses ε-greedy A′

The same policy decides what the agent does and what next action enters the learning target. That is the meaning of on-policy.

CliffWalking intuition: while ε stays above 0, SARSA learns while knowing its own behaviour sometimes explores. Near a cliff, that exploratory behaviour can be costly, so the learned behaviour can become more conservative.

5. Notebook Part C — Q-Learning: almost SARSA, one crucial change

SAME AS SARSA
Q-table, ε-greedy behaviour, TD error, α, γ, episodes, stats.
THE CHANGE
The target uses the best next Q-value, not the next action actually chosen.
RESULT
Behaviour policy and learning target can be different → off-policy.

5.1 Put the two targets side by side first

SARSAQ-Learning
R + γQ(S′,A′)

Use the next ε-greedy action actually selected.

R + γ maxₐ Q(S′,a)

Look across all next-state actions and use the largest Q-value.

Memory trick: SARSA asks “What am I going to do next?” Q-Learning asks “What is the best thing I could do next?”

5.2 Same transition, different learning target

Suppose Q(S,A)=2, reward=−1, α=0.5, γ=1. At S′:

ActionQ(S′,a)
UP8
RIGHT5
DOWN−2
LEFT3

ε-greedy happens to choose RIGHT.

SARSA uses 5

target = −1 + 5 = 4
new Q = 3

Q-Learning uses 8

target = −1 + 8 = 7
new Q = 4.5

Why?

Q-Learning updates toward the greedy target even though behaviour is still ε-greedy.

5.3 Q-Learning update — same three-part reading

Q(S,A) ← Q(S,A) + α [ R + γ maxₐ Q(S′,a) − Q(S,A) ]

Target

Reward + discounted best next-state action value.

Error

Target − current Q(S,A).

Update

Move α of the way toward the target.

5.4 The most important code difference

# ==================== SARSA ====================
# BEHAVIOUR POLICY: epsilon-greedy chooses the action the agent will take.
nextaction = epsilon_greedy_policy(Q, nextstate, epsilon)


# TARGET POLICY: uses that SAME epsilon-greedy A' inside the target.
TD_target = reward + gamma * Q[nextstate, nextaction]


# Because the same A' becomes the next real action:
state = nextstate
action = nextaction
# BEHAVIOUR = TARGET  ->  ON-POLICY


# ================= Q-LEARNING =================
# BEHAVIOUR POLICY: epsilon-greedy chooses the REAL action.
action = epsilon_greedy_policy(Q, state, epsilon)
# env.step(action) will use this behaviour action.


# TARGET POLICY: greedy. It does NOT choose the real next movement.
# It only chooses which next-state Q-value is used for learning.
best_next_action = np.argmax(Q[nextstate, :])
TD_target = reward + gamma * Q[nextstate, best_next_action]


state = nextstate
# BEHAVIOUR != TARGET  ->  OFF-POLICY
Concept clue hidden in the code: SARSA carries state and action forward. Q-Learning only has to carry state forward because it will choose a fresh behaviour action on the next loop.

5.5 Notebook fill-in-the-blanks — completed teaching version

Read the two policies directly from the code:
1. Behaviour policy: epsilon_greedy_policy(...) chooses the REAL action, and that action is passed to env.step(action).
2. Target policy: np.argmax(Q[nextstate, :]) chooses the best-valued next action only for the TD target.
Different rules for the two jobs → behaviour ≠ target → OFF-POLICY.
def q_learning(env, num_episodes, gamma=1.0, alpha=0.85, epsilon=0.1):
    Q = np.zeros((env.observation_space.n, env.action_space.n), dtype=float)


    stats = EpisodeStats(
        episode_lengths=np.zeros(num_episodes),
        episode_rewards=np.zeros(num_episodes))


    for episode in range(num_episodes):
        state, _ = env.reset()
        timeStep = 0


        while True:
            # ===== BEHAVIOUR POLICY =====
            # epsilon-greedy chooses the REAL action A.
            # This is the policy the agent physically follows during training.
            action = epsilon_greedy_policy(Q, state, epsilon)


            # The environment moves because of the BEHAVIOUR action.
            nextstate, reward, terminated, truncated, info = env.step(action)
            done = terminated or truncated


            stats.episode_rewards[episode] += reward
            timeStep += 1
            stats.episode_lengths[episode] = timeStep


            # ===== TARGET POLICY =====
            # Q-Learning does NOT use epsilon-greedy for the target.
            # It asks: "Which action has the largest Q-value at S'?"
            # This greedy choice is used ONLY inside the learning target.
            best_next_action = np.argmax(Q[nextstate, :])


            # BEHAVIOUR policy = epsilon-greedy
            # TARGET policy    = greedy argmax
            # DIFFERENT POLICIES => Q-Learning is OFF-POLICY.
            TD_target = reward if done else reward + gamma * Q[nextstate, best_next_action]
            TD_error = TD_target - Q[state, action]
            Q[state, action] += alpha * TD_error


            # Only the state is carried forward.
            # On the next loop, epsilon-greedy chooses a fresh REAL action.
            state = nextstate


            if done:
                break


    return Q, stats

5.6 Behaviour policy vs target policy — two different jobs

Do not think “I choose one policy and throw the other away.” During Q-Learning training, both policies have a job at the same time:
Behaviour policy = collects experience.
Target policy = tells the update what it should learn toward.
REAL ACTION comes from behaviour policy   →   LEARNING TARGET comes from target policy

Behaviour policy

How the agent actually picks actions to interact with the environment.

ε-greedy

Target policy

The policy the update is learning toward.

greedy max

Therefore

Behaviour policy ≠ target policy → Q-Learning is off-policy.

Plain-English meaning of off-policy: “I can behave using one policy, but learn about a different policy.” Q-Learning may explore with ε-greedy behaviour, while its update learns toward the fully greedy policy.
Q-Learning target = R + γ maxₐ Q(S′,a)
The target ignores which exploratory action will actually be chosen next and uses the best-valued next action instead.
Does “off-policy” mean Q-Learning ignores the actions it actually takes?
No. The real action still creates the reward and next state we observe. “Off-policy” only means the policy used to behave is different from the policy used inside the learning target.

5.6.1 Why do we need a behaviour policy if we eventually follow the target policy?

Short answer: during training, the agent needs a policy that tells it what action to actually take so it can collect experience. That is the behaviour policy. The target policy is the policy Q-Learning is trying to learn about.
DURING TRAINING

Behaviour policy = how I act

Usually ε-greedy.

A = ε-greedy(Q[S])

Most of the time choose the current best action. Sometimes explore a different action.

WHAT I AM LEARNING TOWARD

Target policy = what I want to learn

Greedy with respect to Q.

A* = argmaxₐ Q(S,a)

This is the policy Q-Learning assumes inside its bootstrap target.

Why not just follow the target policy from the beginning? At the beginning, the Q-table is mostly zeros or poor estimates. If we always choose the current argmax, we may keep repeating an action that only looks best because we have not explored the alternatives. The behaviour policy adds exploration so the agent can discover better actions and gather useful rewards.
AT THE START

Target policy is not “smart” yet

If Q-values are all 0, argmax is only breaking a tie. It is not choosing from learned knowledge.

Q(S,:) = [0,0,0,0]
SO WE EXPLORE

Behaviour policy tries alternatives

ε-greedy sometimes chooses a non-greedy action so we can discover rewards and transitions we have not seen.

AS Q IMPROVES

The target becomes useful

argmax Q increasingly represents the best action according to learned experience.

Very important: the target policy is not a separate agent walking around the environment. It is a rule used inside the update: “at the next state, learn as if I will choose the best action.”

One step with numbers

Behaviour actually chooses RIGHT

Because ε-greedy explored.

A = RIGHT

The environment therefore gives the reward and next state caused by RIGHT.

Target looks at the best next action

At S′ suppose:

UP=8, RIGHT=5, DOWN=−2, LEFT=3

Q-Learning uses 8, even if the next behaviour action might not be UP.

Experience came from behaviour  |  Future estimate came from target
This is exactly why it is off-policy: I can learn about the greedy policy from data collected by a different, exploratory policy.
1Behaviour choosesε-greedy picks the real action A
→
2Environment respondswe observe R and S′
→
3Target teachesuse maxₐQ(S′,a) in the update
→
4Q improvesthe greedy target policy becomes more reliable
Think of it like this: the behaviour policy is the explorer. It goes out and gathers experience. The target policy is the policy we are trying to make good. Q-Learning can learn about the greedy target policy from experience generated by a more exploratory behaviour policy.

Does the behaviour policy disappear?

Early training

ε = 0.3

Lots of exploration because Q is unreliable.

Later training

ε = 0.05

Mostly greedy, but still some exploration.

Evaluation / deployment

ε = 0

Use the greedy policy: argmax Q. Now behaviour and target effectively match.

Training: behaviour = ε-greedy   |   target = greedy
After training: behaviour ≈ target = greedy
So why is Q-Learning called off-policy if I eventually follow the greedy policy?
Because off-policy describes how it learns during training. The data can come from an ε-greedy behaviour policy, while the update learns about a different greedy target policy. After training, you can set ε = 0 and actually follow that greedy policy.

5.6.1b Compare this directly with SARSA

SARSA — ON-POLICY

Same ε-greedy policy does both jobs

A = ε-greedy
A′ = ε-greedy

The actual next action A′ is also the action used in the target.

Q-LEARNING — OFF-POLICY

Different rules do the two jobs

A = ε-greedy
target uses max Q(S′,a)

The behaviour action generates experience, but the target assumes the best next action.

Memory line: SARSA learns from what I will actually do next. Q-Learning learns from what would be best to do next.

5.6.2 One training step: where each policy is actually used in code

# 1) BEHAVIOUR POLICY: choose the action we REALLY take
#    epsilon-greedy = mostly greedy, sometimes random exploration
action = epsilon_greedy_policy(Q, state, epsilon)


# 2) Take that action and collect REAL EXPERIENCE
next_state, reward, terminated, truncated, _ = env.step(action)


# 3) TARGET POLICY: ask what the BEST action at next_state would be
best_next_action = np.argmax(Q[next_state, :])


# 4) Learn toward that greedy target
TD_target = reward + gamma * Q[next_state, best_next_action]
Q[state, action] += alpha * (TD_target - Q[state, action])
Notice the separation: epsilon_greedy_policy(...) decides what happens in the environment. np.argmax(...) decides what future value is used for learning. That exact split is the reason Q-Learning is off-policy.

8. Hyperparameters in plain English

α — learning rate

How much one new experience can change the current estimate.

Large α: fast but jumpy. Small α: slow but smoother.

γ — discount

How much the future matters relative to immediate reward.

γ=1 is common for these finite episodic toy tasks.

ε — exploration

Probability of taking a random action under ε-greedy behaviour.

ε=0 means no explicit exploration.
