Monte Carlo Methods

Core idea first, followed by the important parts of the Prediction and Control notebooks.

What is Monte Carlo?

Monte Carlo, or MC, learns from complete experiences. The agent tries the task many times, sees the final results, and averages what happened.

Simple idea: complete an episode → look back at its rewards → learn from the total result.

1. A simple example

Imagine taking the same route to university on many different days. One trip may take 25 minutes, another 35 minutes and another 30 minutes.

Estimated travel time = average of all completed trips

MC works in a similar way. It does not need to know every road or every traffic probability. It learns by completing the journey many times.

2. Important words

EpisodeOne complete attempt, from the starting state to the end. In Blackjack, one episode is one full game.
RewardFeedback received after an action. In Blackjack: +1 for a win, 0 for a draw and −1 for a loss.
Return, GThe total future reward from a particular point until the episode finishes.

3. Why does MC wait until the end?

MC learns from the full return. The full return is only known after the episode finishes.

MC does not update after only seeing the next reward. It waits for the complete result.

4. Return and discount factor

Gₜ = Rₜ₊₁ + γRₜ₊₂ + γ²Rₜ₊₃ + …

The first reward is received next, so it has no discount. A reward that is further away is multiplied by gamma more times.

γ = 1All later rewards keep their full value.
γ below 1Rewards further in the future count less.
Gamma is not a transition probability. It only controls how strongly future rewards are valued.

5. What makes MC different?

FeatureMeaning
Model-freeIt does not need a table of transition probabilities or expected rewards.
Uses complete episodesIt learns after reaching the terminal state.
No bootstrappingIt uses rewards that actually occurred, not an estimated value of the next state.
SamplingOne episode can be lucky or unlucky, so many episodes are averaged.

6. Prediction and control

MC PredictionChecks how good a fixed policy is. It learns V(s): the value of being in a state.
MC ControlLearns which action is better. It learns Q(s,a): the value of taking an action in a state.
Order: first understand how MC evaluates experience, then use the same idea to improve decisions.

Updating the value of a state

▼

Each time state S is accepted, it gives us one return, G. V(S) is simply the average of the returns collected for S.

Returns for S: 4, 2, 7   →   V(S) = (4 + 2 + 7) / 3 = 4.33

The code produces the same average one return at a time. It does not need to save the full list.

new V(S) = old V(S) + [new G − old V(S)] / new N(S)
# Move backwards through the completed episode
for t in range(len(states) - 1, -1, -1):
    # Current reward + discounted rewards that come later
    G = rewards[t] + gamma * G
    S = states[t]

    # One more accepted return has been collected for this state
    N[S] += 1

    # Update the average without storing all the old returns
    V[S] += (G - V[S]) / N[S]
N(S)How many accepted returns have been used for this state.
V(S)The average of those accepted returns.

Build the average slowly

Returns for state A: 4, 2, 7

Nothing has been added yet. N(A) = 0 and V(A) = 0.
Do not overthink the formula: it is only a running average. N counts the returns and V stores their average.

First-Visit versus Every-Visit

▼

This difference matters only when the same state appears more than once in one episode.

Episode: A → B → A → terminal
MethodWhat happens to A?
First-VisitA is updated once, using the return from its earliest occurrence.
Every-VisitA is updated twice, once for each occurrence.
# First-Visit: update only if S did not appear earlier
if S not in states[:t]:
    N[S] += 1
    V[S] += (G - V[S]) / N[S]

# Every-Visit: no condition; update every occurrence
N[S] += 1
V[S] += (G - V[S]) / N[S]
First visit means first in the original forward episode. It does not mean the first item processed by the backwards loop.
Episode returns: A₀=6, B=5, A₂=3.

N and First-Visit, in the simplest way

▼

What is N?

N[A] answers one question: “How many returns have been used to calculate V(A)?”

N[A] = 2Two accepted returns have been averaged for A.
V(A) = 3If those returns were 4 and 2, their average is 3.
Every state has its own count. N[A], N[B] and N[C] are separate.

Does First-Visit mean N[A] always stays 1?

No. It means “use A only once in each episode”, not “use A only once forever”.
EpisodeWhat happened?First-Visit choiceN[A]
1A appeared twiceUse the first A only1
2A appeared onceUse A again2

After two episodes, A has supplied two accepted returns. Therefore, N[A] = 2.

First-VisitAt most one update for A in each episode.
Every-VisitUpdate A every time it appears.

Why does the code increase N first?

# A new accepted return has arrived
N[S] += 1

# Include it in the running average
V[S] += (G - V[S]) / N[S]

If a second return arrives, N must become 2 before the code calculates the average of two returns.

A appears twice in Episode 1 and once in Episode 2. What is N[A]?

First-Visit: N[A] = 2. One accepted A from each episode.

Every-Visit: N[A] = 3. All three appearances are accepted.

Why control uses Q instead of V

▼
V(s)How good is this state?
Q(s,a)How good was one particular action in this state?

Blackjack has two actions, so Q stores two averages for each state:

Q[state] = [average return after stick, average return after hit]

For example, if Q is [0.6, 0.2], stick has produced the better average return.

policy(state) = action 0 = stick
Prediction averages returns by state. Control averages returns by state and action.

Updating Q from an episode

▼

The return is calculated in the same way as prediction. The difference is that the update belongs to a state-action pair.

Q(S,A) ← Q(S,A) + [G − Q(S,A)] / N(S,A)
# Work backwards through the completed game
for state, action, reward in reversed(episode):
    # Calculate the return from this point
    G = reward + gamma * G

    # Count this exact state-action pair
    N[state][action] += 1
    alpha = 1 / N[state][action]

    # Move Q towards the observed return
    Q[state][action] += alpha * (
        G - Q[state][action]
    )
N is also separate for each action. N[state][hit] counts returns collected after hitting in that state. N[state][stick] is a different count.

The same running average as Prediction

Suppose the pair (state A, hit) receives returns 1, 0 and 1:

Q(A, hit) = (1 + 0 + 1) / 3 = 0.67
Nothing added yet. N(A, hit) = 0 and Q(A, hit) = 0.
The averaging idea has not changed. Prediction updates V(S). Control updates Q(S,A).

Calculate G first: rewards [0, 0, 1], γ=0.9

Start with G = 0.

The complete control loop

▼
  1. Generate a complete episode using ε-greedy actions.
  2. Calculate the returns backwards.
  3. Update the Q-values of the actions that occurred.
  4. Reduce epsilon slightly.
  5. Repeat for many episodes.
  6. Choose the highest-Q action in every state.
for episode_number in range(episodes):
    # Collect one complete game
    episode = generate_episode(env, Q, epsilon)

    # Learn the values of the actions used
    update_Q_values(episode, Q, N, gamma)

    # Become less random over time
    epsilon *= decay

# Final greedy policy
policy[state] = np.argmax(Q[state])
Control repeatedly evaluates actions and improves behaviour. Better Q estimates influence how later episodes are played.

Debug the MC code

▼

Each snippet contains one issue.

A. Return calculation

for t in range(len(states) - 1, -1, -1):
    G += rewards[t] * (gamma ** t)
When looping backwards, use G = rewards[t] + gamma * G. The exponent should depend on distance from the current state, not the original time index.

B. First-Visit condition

if S not in states[t + 1:]:
    update_V(S)
This checks whether S appears later. First-Visit must check whether it appeared earlier: S not in states[:t].

C. Gymnasium termination

next_state, reward, terminated, truncated, info = env.step(action)
done = terminated
The episode should stop for either condition: done = terminated or truncated.

Knowledge checks

Why does MC normally wait for an episode to finish?
Because it needs the complete return from the current point to the end.
What is the difference between First-Visit and Every-Visit?
First-Visit updates a state once per episode. Every-Visit updates it every time it occurs.
Why does control use Q?
Q gives a separate value to each action, allowing the agent to compare actions directly.
Why is ε-greedy needed?
It allows the agent to explore instead of permanently trusting incomplete early estimates.
